# CRM（顧客管理ページ）リニューアル 設計メモ

作成: 2026-09-13　更新: 2026-09-17

状態: **ルールを1つずつ決めながら、決まったところから実装している。**
LINE側の入口（挨拶・リッチメニュー・空室確認・お部屋マップ・登録だけの人への催促）は稼働中。
CRM画面そのもの（カンバンの作り直し）はまだ手を付けていない。

目的: 「どのお客さんに何をやればいいか」が一目で分かる顧客管理にする。
今のカンバン（列で扱いを表す方式）は、列を増やしても判断が楽にならなかった。

## 骨格（優秀なCRMの型を採用）

1. **工程と扱いを分ける** — 列は「お客さんが今どの工程にいるか」だけ。どう扱うかは機械が計算する
2. **次のアクティビティが必ず入っている** — 次回接触日が空の人をゼロにする
3. **ケイデンス** — 反響から「直後→平日→土日」のように決めた順で連絡する
4. **腐り検知** — 一定日数動きがないと赤くする
5. **やることは3箱** — 期限切れ／今日／これから

### 工程（列）は6つに減らす

```
反響 → 追客中 → 内見 → 申込 → 成約 ／ 失注
```
- 「時期待ち」は列ではなく保留フラグ（期限が近づいたら自動で戻る）
- 「未反応」「条件確定」「条件調整中」は列を廃止し、表示上の印にする

### 画面（案3: 2画面）

左に「やること」（期限切れ／今日／これから）、右にその人の詳細と1タップ操作。
今のカンバンは残し、別URLで並行して使う。落ち着いたら入口を切り替える。

## 顧客の種類と扱い（ユーザー案・2026-09-13）

### ① 未接続（LINEに来ていない）

| 種類 | 扱い | 抜け方 |
|---|---|---|
| メールだけ | 自動メール（今のフォローアップ）。人は触らない | LINEに来たら② ／ 一定期間来なければ失注 |
| 電話もある | 架電3回（早めに1回・平日1回・土日1回）。メールも並行 | LINEに来たら② ／ 3回つながらなければ失注 |

### ② LINEに来た

| 種類 | 扱い |
|---|---|
| 登録だけ | 条件登録の案内を1回リマインド。反応がなければ失注（2026-09-19 変更） |
| 空室確認だけ | 結果を返したあと条件登録へ誘導。反応なしならリマインド1回 |
| 条件登録済み | → ③ |

### ③ 条件登録済み

| 種類 | 判定 | 扱い |
|---|---|---|
| 優先 | 連絡がつく（直近の受信・通話あり）または 引越し期限が近い | 人が毎日見る。やることに出る |
| 通常 | それ以外 | 自動に任せる。強い合図が出たときだけ人が動く |

## 確定したこと（2026-09-16）

- **① メールだけ**: 自動メール14日、LINEに来なければ失注。統合されたら③になりメールは止まる（実装済み v1554/v1555）
- **① 電話あり**: 早めに1回・平日に1回・土日に1回架電。つながらなければ失注
- **③ の分け方**: 「ちゃんと探してる人／そうじゃない人」（判定材料は未定）

### 空室確認の作り替え（確定・実装済み GAS v1557 / `VacancyRequest.js` `VacancyAnswerPage.html`）

背景: 挨拶で「条件登録」と「メールアドレス送信」の2つを頼んでいて分かりにくい。
メールアドレスは空室確認の入口でもらい、反響と突き合わせて本人を確定する。

- 電話で問い合わせた人は電話で答えているので対象外
- **入口（本人未確定）**: 「お問い合わせ時のメールアドレスを送ってください」＋ボタン「別の物件を調べる」
  - 一致 → 問い合わせた物件をボタンで並べる＋「別の物件を調べる」。ここで統合・メール停止も自動
  - 一致なし → 「見つかりませんでした」→ 物件名/URL入力へ
- **入口（本人確定済み）**: メアドは聞かず、問い合わせた物件のボタン＋「別の物件を調べる」
- **別の物件**: 「物件名、またはSUUMOやHOME'Sなどの物件ページのURLを送ってください」
  - 1通に複数（URL・行）あればまとめて1件の依頼にする（上限10件）
  - 自社シート（物件空室管理）にあるものは先に自動判定し、依頼に結果を添える
  - シートに無くても「見つかりません」は出さず、そのままスタッフへ。お客さんには「お調べしてご連絡します」の1通だけ
- **Discordの依頼**: 番号付きで並べ、各番号に「募集中／ご案内不可」の2択。募集終了と他社専任は区別しない
- **お客さんへの返事は1通に合成**
  - 募集中あり: 募集中だけ並べ、最後に「それ以外の物件は現在ご案内できませんでした」
  - 全部不可: 「いずれも現在ご案内できませんでした」＋条件登録への誘導
  - 任意の「ひと言」欄。定型に収まらなければ自由文で返す道も残す
  - スタッフが「送信」した分: **自社シートに無い物件だけの依頼はその場で送る（営業時間も関係なし）**。
    自社シートにあるが自動判定できなかった（要確認）物件を含む依頼は従来どおり 5分遅れ・営業時間内 のキュー。
    自社シートだけで自動判定できた分も同じキュー
- 挨拶の「メールアドレスを送ってください」push は廃止し、挨拶は「空室確認」「条件を登録」の2択に絞る

### 挨拶とリッチメニュー（確定・実装済み GAS v1565 / `RichMenu.js`, 画像は `docs/richmenu/`）

- 挨拶（公式アカウントマネージャーで設定）: 短い文章＋「どっち？」画像（greeting.png）。最後に「ご質問はそのままLINEへ。担当者が返信します」
- リッチメニューは2段階。登録前 = 空室確認／条件を登録（2枠）。登録後 = 空室確認／条件を変える／お気に入り／配信の停止・再開／使い方（5枠）
- 条件登録が完了した時点（writeToSheet）で登録後メニューに自動で切り替える
- 登録前の人が「使い方」を押したら「どっち？」画像を返す
- 「担当者に相談」ボタンは入れない（普段からLINEで普通に会話しているため）。代わりに挨拶と登録完了メッセージに「担当者が返信します」の一文
- 自由文をDiscordに流すことはしない（ユーザー判断）
- 初期設定は GASエディタ `RichMenu.gs` の `setupRichMenus()` → `bulkLinkRegisteredUsersToAfterMenu()`

### お部屋マップの公開（確定・実装済み GAS v1566）

- これまで社内下見用だった `map.html` を、登録後リッチメニューの6枠目「お部屋マップ」としてお客様に開放する
- タップ → ボットがその人の地図リンク入りカードを返す → ボタンで開く（1タップ増える）。
  リッチメニューは全員で同じURLを共有するため、固定URLではタップした人を特定できない。
  直接開くには LIFF が要るが、初公開は「何が見られるか」を説明できるカード方式で始める
- LIFF に切り替える場合: LINEログインチャネル＋LIFFアプリを作り、`RichMenu.js` の `MAP_LIFF_CONFIG`
  （liffId / loginChannelId）と `docs/map.html` の `MAP_LIFF_ID` に入れて `setupRichMenus()` を再実行する。
  検証用エンドポイント `?action=map_token_by_line` は実装済み
- 地図を開いたことは既存の仕組みでDiscordに静かに通知される（30分よけつき）

### ② LINEに来た / 登録だけの人（確定・実装済み GAS v1586 / `NewFriend.js`）

過去に止まっている人には触らない。これ以降の友だち追加だけを記録して対象にする。

- **対象**: 友だち追加のあと、空室確認も条件登録も始めていない人。メニューを押しただけで止まった人は
  フローの状態が残るので「途中離脱」側が受け持ち、こちらには入らない
- **タイミング**: 追加から16時間後、営業時間内。日中に追加した人は必ず翌日の10時以降になる
- **送るもの**: ボタン2つ入りのカードを1通だけ（押しメッセージは1通ぶん課金されるため1つに収める）
  ```
  友だち追加ありがとうございます

  気になるお部屋の空き状況をお調べできます。
  ご希望の条件を登録いただくと、条件に合うお部屋が出たときにお知らせします。

  [ 空室確認する ] [ 条件を登録する（3分） ]
  ```
  ボタンは「空室確認」「条件登録」を送るので、リッチメニューと同じ流れに入る。
  ⚠️ 「お問い合わせいただいた物件」とは書かない。電話・紹介の人に噛み合わないため
- **送らない相手**: 条件が登録されている人（担当者の代理登録を含む） ／ 直近16時間にお客様から
  何か届いている人（担当者との会話に割り込まない。次回に持ち越す） ／ フローの途中にいる人
- **反応が無かったら**: 何もしない。二度目は送らず、失注にもしない。数は `showNewFriendStats` で追える
- 電話のお客様は、通話中にLINEを追加してもらい、**LINEのIDを管理画面に入れて即座に条件登録**する運用。
  これでリッチメニューの切り替えも催促の停止も効く。IDを入れずに名前だけで登録すると
  どちらも効かない（警告ログが出る）

### ② LINEに来た / 空室確認で止まった人（文面確定・送信は未開始）

空室確認の途中離脱は3通り。いずれも翌日に1回だけ。二度目は送らない。

| 止まった場所 | 送るもの |
|---|---|
| メールアドレス待ち | 「空室確認のご依頼ありがとうございます。」＋メールアドレスが要る理由を添えて依頼 |
| 問い合わせ物件のボタン | 同じボタンをもう一度出す（物件名を聞き直さない） |
| 物件名やURL待ち | 「空室確認のご依頼ありがとうございます。」＋物件名かURLを依頼 |

- ⚠️ 「すぐお調べします」とは書かない。自社の掲載物件でなければスタッフが調べるため
  すぐとは限らない。実際に返す「お調べしてご連絡します」に言い方を揃える
- メールアドレスが一致しなかったときの返事は「見つかりませんでした」で突き放さない。
  別のアドレスで問い合わせた・電話で問い合わせた・紹介で来た、はどれも普通にある。
  24時間の受付期限は残す

**失注の扱い（2026-09-19 変更）**: ⚠️ 2026-09-16 の判断（「自動で失注にする仕組みは今は作らない」
「登録だけの人は動きなしでも失注にしない」）を取り消す。

**ゴールは契約か失注のどちらかだけ。宙ぶらりんの人を残さない。**
催促は1回だけ。それを無視されたら失注につなげる。対象は4つとも同じ扱い。

| 止まった場所 | ひと押し | そのあと |
|---|---|---|
| LINEに来ない | 自動メール14日・架電3回 | 失注 |
| 登録だけの人 | 16時間後に案内 | 失注 |
| 途中でやめた人 | 翌日に質問を再送 | 失注 |
| 空室確認だけの人 | 翌日にもう一度案内 | 失注 |

**未定（2026-09-19 時点）**: 催促してから何日で切るか。**これは画面を決めてからでないと決まらない。**

- 「失注」の手前に**休眠**を挟む案が出ている。催促の翌日に自動で休眠、LINEにアクションがあれば自動で復活。
  失注は担当者が理由を選んで手で落とすものとして残す（休眠を失注に混ぜると失注率が指標として使えなくなる）
- ⚠️ 今の看板のまま「終了」に落とすと、`autoArchiveFinishedCustomers` が翌朝5時に経過日数0で
  アーカイブする。アーカイブするとブロック解除の自動復活も効かなくなる（コード.js のコメント参照）ので、
  自動で復活させるにはアーカイブ対象から外すか、アーカイブ解除まで作る必要がある
- やること3箱の画面にするなら、休眠＝**次回接触日を持たない状態**で済み、アーカイブ自体が要らなくなる
- メールだけの人には当てない。LINEに来ていないので復活の合図を拾えない。今の14日のままにする
- 条件登録済みの人にも当てない。「終了」は物件の自動送付を止める（コード.js:2490 / 2583）。
  途中離脱の対象には登録済みが混ざる実績がある（実測146人中59人）

**計測を開始（実装済み GAS v1634）**: `LINE友だち追加` シートに「ひと押しした日時」「ひと押しの種類」の
2列を追加した。状態（4・5列目）は動きがあると上書きされ、催促の日時が消えていたため別に持つ。
2〜3週間ためて `showNudgeResponseDays()`（NewFriend.gs）で「動く人は催促の何日後に動くか」を見る。
理由は、メールアドレスが一致した時点でLINEと顧客カードが結びつき、カンバンの「未反応」に
現れるため。未反応は毎日チェックする列なので担当者の目に触れ、見えなくならない。

積み残し（CRM作り直し時に扱う）:
- LINEに来たが条件登録していない人を、いつ失注にするか
- 結びついた時点でフォローアップメールが止まる。自動の接触回数が減ることの是非
- 「未反応」という列名が実態と合っていない（LINEに来てメールアドレスまで送った人が入る）

### ② LINEに来た / 途中でやめた人（実装済み・送信は未開始 `NewFriend.js`）

会話の状態（`state_<userId>`）を見て、止まった場所に合わせた文面を翌日に1回だけ送る。
担当者と会話している人は状態を持たないのでぶつからない。
状態が残っているだけで実は登録済みの人が混ざるため（実測146人中59人）、送る前に必ず確かめる。

実測: 本当に途中でやめているのは87人（条件登録67・空室確認20）。約2か月ぶんなので1日1〜2人。
最多は条件選択ページを開いたまま送信しなかった人。次が1問目の「お部屋探しの理由」。

- 開始前に `markExistingFlowsAsNudged()` を1回実行する（過去の87人に送らないため）
- `cleanupOldConversationStates()` で古い状態を掃除できる（上限500KB、現在62KB）

**文面（確定）**
- 条件登録の質問の途中: 止まっている質問そのものを出し直す。`showStepQuestion` の送信口を
  一時的に差し替えて中身を受け取り、押し通知で送る（質問文・選択肢・進捗ゲージが本家とずれない）。
  頭に次の2行を足して1通に収める。「ご回答ありがとうございます」は1問目で止まった人に
  噛み合わないので使わない
  ```
  お部屋探しのご希望をお伺いしています。
  お答えいただくと、ご希望に合うお部屋をお探しします。
  ```
- **入居申込の途中は催促しない（2026-09-17 確定）。** 物件カードの「入居申込をする」は
  試しに押す人が混ざるうえ、申込は契約に向かう一歩で自動で追うのは踏み込みすぎ。
  完了すればLINE公式アカウントの通知で担当者が気づける。
  設計メモの「申込／内見の画面を開いて送らなかった → 当日中に電話」とも揃う
- 配信停止まわりの途中も催促しない
- 条件選択ページ: カード＋ボタン「条件の登録を完了させる」
  ```
  ご回答ありがとうございます

  エリア・家賃・間取りなどをお選びいただくと、ご登録が完了します。

  スタッフが厳選したお部屋をお送りします。
  検索サイトに出ていないお部屋もご紹介できます。
  ```
- `previewAbandonedRemind()` で送らずに8通りの中身を確認できる

**会話状態の期限（実装済み GAS v1593）**
- **条件登録（`STEP_*`）は期限で消さない。** 何か月後でも選択肢をタップして続きから進める
- **自由入力の受け取りだけ24時間で止める。** 理由・居住者の自由入力、その他ご希望の3か所。
  期限を過ぎた文は答えとして保存せず、「お時間が空きましたので、念のためもう一度お伺いします。」と
  添えて質問を出し直す。何か月も前の質問に無関係なメッセージが登録される事故を防ぐ
- 空室確認・入居申込・配信停止まわりは従来どおり24時間で消す（自由入力を受け取る場面が多いため）
- **途中の人がメニューから「条件を登録」を押したら、今までどおり最初からやり直す。**
  「続きから再開しますか」とは聞かない。前半は4問のタップだけで復元の利得が小さく、
  何より引越し時期などの古い回答を復元しない方が正確なため

## 他社物件の「近い条件」（2026-09-19 確定・実装済み GAS v1629）

②空室確認だけの人への催促は「どのサイトのお部屋でも」と案内している。つまり送られてくるのは
他社物件が中心で、自社の物件空室管理シートに無いため `_propertyToCriteria_` が条件を作れず、
ひと押しで登録が終わる2択カードにならず「お部屋を探す」の1択カードになっていた。

**決めたこと: スタッフが回答フォームで入れる。任意。**

- 回答フォーム（`?action=vacancy_answer_form`）に 路線・駅・賃料＋管理費・間取り・専有面積・築年数・駅徒歩・こだわり の欄を足した
  （自社物件から自動で作るときと同じ項目数。条件が細かいほど「この条件で探してもらえる」と伝わって押されやすいため、
  少ない項目で済ませない）
- 出るのは「1件の依頼をご案内不可で返すとき」だけ。募集中や複数件のときは出ない
- 全部任意。面倒なら空のまま送れる。空なら今までどおり1択カード
- 2択カードになる条件: 路線と駅が入っていて、賃料か間取りのどちらかがあること
  （エリアの無い条件は自動検索がスキップするので登録しても意味がない）
- 「はい、お願いします」には依頼ID（`vreq`）を持たせ、押された時にシートから条件を読み直す
- 成績は `showVacancyCardStats`（CardStats.gs）で「条件あり(スタッフ入力)」として別に数える

**自動取得はサイトごとに足していく。今は HOME'S・SUUMO・athome の3つ。**

実測（2026-09-19・吉祥寺の実在物件）:

| サイト | 題名・概要から取れるもの |
|---|---|
| HOME'S | 賃料・管理費・間取り・面積・沿線駅・徒歩・築年月・設備 — 全部 |
| athome | 賃料・管理費・間取り・面積・沿線駅・徒歩・築年月・設備 — 全部（実測4件） |
| SUUMO | 賃料・管理費・間取り・面積・沿線駅・徒歩・築年月・設備 — 全部（実測5件） |

## 決まったルール

- **A 反響**: 営業時間内は1時間以内、時間外は翌営業日午前に架電。つながらなければ 直後→平日→土日 の3回。3回ダメで LINEあり→追客中、LINEなし→失注
- **B 送付後の合図**: 電話するのは強い合図のときだけ
  - 申込／内見の画面を開いて送らなかった → 当日中に電話
  - 同じ物件を3回以上、または3件以上開いた → 当日中に電話（ダメならLINE）
  - 1件見ただけ → 何もしない（印だけ）
  - 開いていない → 翌日に1回だけひと言。それ以上追わない
- **C LINE受信**: 受信は自動で記録できる（webhook）。返信済みかは自動では分からない → 既存の✓完了で消す。こちらから送った分の追いはルールにしない（送るときに次回接触日を入れるかで決める）
- **D 送れる物件がない**: 7日で近況ひと言、14日で条件を広げる提案
- **E 引越し期限**: 60日前で間隔を半分、30日前で毎日、14日前は時期確認のみ（返事なしで保留か失注）
- **F 温度感**: 間隔は変えない。記録だけ（なくてもよい）
- **G 1タップ記録**: 📞話せた／📵つながらず／📨LINEした／👀内見（予定・結果）／✋失注（理由）。どれもそのあと次回接触日を選ぶ
- **H 内見**: 内見希望ボタンは合図であって記録ではない。担当者が予定（日付・物件）→結果（申込／見送り／流れた）を入れる。前日に確認連絡、翌日に結果を聞く、がやることに出る

## 取る材料（追加）

1. お客様からのLINE受信日時 — 自動（webhookで来ている）
2. 次回接触日 — Gのタップ時に必ず入れる
3. 内見の予定と結果 — 担当者が入力
4. 失注理由 — ✋のとき選ぶ
5. 温度感 — 任意
- 架電可能時間帯は取らない（ほとんどつながらないため）

## まだ決めていない数字

1. ①メールだけ: LINEに来なければ失注にするまで何日
2. ②登録だけ／空室確認だけ: リマインドは何日後（案: 3日）
3. ③優先の判定: 直近何日以内の受信・通話（案: 14日）／引越しまで何日以内（案: 60日）
4. ③通常で自動提案が出尽くしたあと（今は10日×3回）: 保留にして寝かせるか
5. 自動提案の頻度と期間の見直し（案1: 7→14→21日で3回、反応なしで保留）
6. 失注理由の選択肢（案: 他社で決めた／条件が合わない／連絡つかず／時期延期／予算／その他）
