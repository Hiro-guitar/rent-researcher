## このセッションでやったこと

### 1. 空室確認の自動LINE誤送信を停止（重要な不具合修正）
- **要確認物件**（REINS等、自動で空室判定できないもの）が、スタッフ向けDiscordに出すのと**同時に遅延返信キューにも入っていた**ため、スタッフ未対応でも約4分後に顧客へ「ご案内不可」が自動送信されていた
- `ExistingBot.js` の `handleVacancyQuery` で、要確認は遅延キューに入れないよう修正（手動返信のみ）

### 2. 駐車場を条件に追加（全サイト対応・実データ検証済み）
条件登録フォーム / 検索条件管理 / おすすめ条件（裏条件）すべてに「**駐車場あり**」＋**車種（必須入力）**を追加。

| サイト | 実装 | 検証 |
|---|---|---|
| REINS | 「有／空有」(value=1)と「近隣確保」(value=3)の**2パス検索**。近隣確保は⚠️アラート | Claude in Chrome実地調査（574→82/6件） |
| itandi | `parking_exists:eq: true` で絞り込み（設備IDではなく独立チェックボックス） | 実API（1499→172件） |
| いえらぶ | `pkcd=1`(空有) と `pkcd=3`(近隣) の**2パス検索**。近隣は⚠️アラート | 実フォームでパラメータ確認 |
| いい生活 | `kodawari=chushajoExist` | 実データ（14→9件） |

- REINSの駐車場セレクトは**ラベル「駐車場の有無」からの相対取得**（BootstrapVueのidは不安定なので使わない）。native change で Vue の iValue も同期する
- 駐車場を希望しない顧客の検索でも毎回「未指定」を明示セット（前顧客の値が残る事故防止）

### 3. 独立洗面台の skip/alert 切替
バス・トイレ別(btMode)と同じ仕組みで `senmenMode` を追加。**既定は alert（アラートのみ）**。

- REINS: 設備欄に「独立洗面台」という項目は無く、実語彙は **洗面所/洗面台/シャンプードレッサー**。既存の3段階警告（確実あり／洗面台のみ=ユニットバス可能性／記載なし）が元からあったので、それに一本化。skipでも**洗面系の記載が一切ない物件だけ除外**
- itandi: skip時は設備ID **11060** をhardに昇格してAPI検索条件へ（実フォームでvalue確認済み）
- いい生活: skip時は `kodawari=separatedLavatory`
- いえらぶ: 洗面系の選択肢が10種以上あり検索で絞ると取り逃すため、**検索では絞らず取得後フィルタ**（意図的）

### 4. itandiのペット判定を変更
詳細に「**ペット対応**」とだけ書かれ設備ID(22010)が付いていない物件が、API絞り込みで消えていた（ユーザーが実確認）。
→ 22010をsoft化して**APIでは絞らず**、取得後のテキスト判定（ペット相談/ペット可/ペット対応/小型犬/大型犬/猫可 を許可、ペット不可・記載なしは除外）に変更。

### 5. 階数の指定（2種類）
| 欄 | 用途 | 例 |
|---|---|---|
| **◯階以上**（minFloor） | 「3階以上」など普通のケース | `3` |
| **希望階数**（allowedFloors） | 飛び飛びの指定 | `3,5,6,7,8,11` |

- あわせて **部屋番号の数字合計**（roomDigitSums）フィルタも追加（例: 305号室→3+0+5=8）。特定顧客（小川英利さん）の要望
- 検索段階でも下限で絞る: REINS所在階From / itandi `floor:gteq` / いえらぶ `flnuf` / いい生活は下限2以上なら `floorSecondOrAbove`
- **階数・部屋番号が取得できない物件は誤除外を避けるため通す**（他フィルタと同じ方針）
- 顧客向けの条件登録フォーム(criteria.html)には**入れていない**（一般顧客が混乱するため管理画面のみ）

### 6. CRM関連
