# 内見希望ボタン 仕様メモ（2026-08-01 実装）

顧客向け物件ページ（`form.ehomaki.com/property.html`）に「この物件の内見を希望する」ボタンを追加した。
このファイル単体で経緯と挙動が分かるように書いてある。

---

## 1. なぜ作ったか

物件ページの選択肢が **「お申し込み希望」（重い）** と **「お気に入り」（こちらが動く理由にならない）** の二択しかなく、
実際の検討段階にあたる受け皿が無かった。

- カンバンに「内見」ステージはあるのに、そこへ流れ込む導線が存在せず 0 件のままだった
- 「内見希望が入りました」は担当者が電話をかける理由として最も強い

なお `viewing`（内見希望）という種別自体は以前から各所に配線済みで、**ボタンだけが無い**状態だった。

## 3. 顧客から見た流れ

1. 物件ページの緑の「この物件にお申し込み希望をする」の下に、青枠の **「この物件の内見を希望する」** が出る
   （画面下の追従バーにも「内見を希望」として出る）
2. 押すとモーダルが開く

```
内見のご希望
ご希望の日時をお聞かせください。
┌──────────────────────────────────┐
│ 担当者が空き状況を確認のうえ、        │
│ お電話にてご連絡いたします。         │
│ お日にちは、その際にご相談させて      │
│ いただきます。                     │
└──────────────────────────────────┘
[ お名前（必須）                    ]
[ 電話番号（必須）                  ]
[ 希望日（必須） ] [ 時間帯 ▾ ]
内見のご案内は 11:00〜18:00 で承っております。
それ以外のお時間も物件によってはご相談いただけます。
[ 他の候補日や、ご希望のお時間・ご要望（任意） ]
        [ 内見希望を送信 ] [ キャンセル ]
```

3. 送信するとトーストが出て、ボタンが「✅ 内見希望を受付済み」になる
4. LINE にも受付確認が届く

### 入力項目

| 項目 | 必須 | 内容 |
|---|---|---|
| お名前 | ✅ | 自由入力 |
| 電話番号 | ✅ | 形式チェックあり（申込フォームと同じ `validatePhone`） |
| 希望日 | ✅ | `<input type="date">`。**過去日は選べない**（`min` を当日に設定） |
| 時間帯 | — | 11:00〜18:00 の30分刻み15枠 ＋「いつでも可」の16択 |
| 備考 | 任意 | 他の候補日・時間外の相談など |

必須3項目は **冷やかしを弾く意図**で必須にしてある。埋めないと送信できない。

## 4. 通知の挙動（申込と同じ設計）

| タイミング | action_type | Discord | 通知音 |
|---|---|---|---|
| モーダルを開いた瞬間 | `viewing_intent` | 飛ぶ | **鳴らない** |
| 送信した瞬間 | `viewing` | 飛ぶ | **鳴る** |
| （参考）申込を開いた | `hold_intent` | 飛ぶ | 鳴らない |
| （参考）申込の送信 | `hold` | 飛ぶ | **鳴る** |
| （参考）閲覧・お気に入り | `view` / `favorite` | 飛ぶ | 鳴らない |

音の制御は `PropertyApproval.js` のここ一箇所：

```js
// hold と viewing 以外はサイレント送信（SUPPRESS_NOTIFICATIONS）
if (actionType !== 'hold' && actionType !== 'viewing') {
  payload.flags = 4096;
}
```

### 送信時の Discord 文面

```
@担当 🔑 **Hiroki** 様が「パークキューブ西新宿 1002」の **内見をご希望** です！
> 🗓 希望日時: **2026-08-05 15:00**
> 備考: 8/6の夕方以降でも可能です
> 氏名: 西村 拓
> 📞 Tel: 090-1234-5678
> → 空き状況を確認のうえ、お電話で日程調整をお願いします
> 15万円 / 1K (2026/08/01 18:30:00)
```

そのまま架電できる形にしてある。

### 開いただけの Discord 文面

```
@担当 👀 **Hiroki** 様が「パークキューブ西新宿 1002」の **内見希望画面を開きました**（未送信）
```

入力せず離脱した人を拾うため。音は鳴らない。

### 顧客へのLINE受付確認（送信時のみ）

```
🔑 内見のご希望を承りました
─────────────────
パークキューブ西新宿 1002
ご希望日時: 2026-08-05 15:00
─────────────────
担当者よりお電話にてご連絡いたします
空き状況を確認のうえ、お日にちはその際にご相談させていただきます。
```

**「まだ確定していない」ことを、送信前のモーダル・送信後のトースト・LINE の3箇所すべてに明記している。**
送信しただけで予約が取れたと受け取られると当日に行き違いが起きるため。

## 5. データの残りかた

アクションログ（スプレッドシート「アクションログ」）に1行追加される。

| 列 | 値 |
|---|---|
| C: アクション | `viewing`（開いただけなら `viewing_intent`） |
| K: 連絡先 | `氏名: 西村 拓 / Tel: 090-1234-5678 / 内見希望: 2026-08-05 15:00 / 備考: ...` |

希望日時は専用列を作らず**連絡先欄にまとめて入れている**ので、ログを見れば要件が分かる。

**カンバンの営業ステージは自動では動かない。** 希望した時点では日程未定なので、
通知を見て担当者が手で「内見」へ移す前提。

## 6. 実装上の注意（触るときに壊しやすい点）

### ⚠️ 入力欄を初期HTMLに置かないこと

過去に**申込フォーム（氏名・メール・電話）を初期HTMLに置いたことで Google Safe Browsing に
フィッシング判定された経緯がある**（commit `00a3c2a` でオンデマンド生成にして解消）。

内見モーダルも同じ方式を守っている：

- `buildViewingModalHtml()` が HTML 文字列を返すだけ
- `ensureViewingModal()` がボタンを押した瞬間に生成して `document.body` に挿入
- **初期HTMLには `<input>` / `<textarea>` / `<select>` が1つも存在しない**

ここを崩すとページ全体が警告表示になり、全顧客に影響する。

### 申込とは独立した状態で管理している

内見の完了状態は `viewingDone`（localStorage キー `viewingReq:<customer>:<roomId>`）で持ち、
申込の `actionState` とは分けてある。

当初 `updateActionUI` が `viewing` を `hold` と同一視しており、
**内見を送ると申込ボタンが「✅ お申し込み希望受付済み」になって申し込めなくなる**不具合があった。
現在は `viewing` を受け取ったら内見ボタンだけ更新して抜ける。

### Discord の文面テーブルに登録し忘れると握り潰される

`msgMap` に該当の `action_type` が無いと `msg` が空になり、早期 return で**何も通知されない**。
新しいアクション種別を足すときは必ず `msgMap` にも追加すること。

### 追従バーのボタンはラベルが別

画面下の追従バーは幅が狭いので短いラベルを使う。
`data-label` / `data-label-done` を持たせてあり、`updateActionUI` / `renderViewingBtns` は
そちらを優先して書き換える。クラス（`.viewing-btn`）は同じなので状態は自動で同期する。

## 8. 既知の粗さ

- 申込不可の物件でボタンが「キャンセル待ち通知を申請する」に変わる場合、追従バーでは文言が長く
  2行になる。表示は崩れないが、頻度を見て詰める余地あり
- 内見希望からカンバンの「内見」ステージへの自動連携は入れていない（意図的）
