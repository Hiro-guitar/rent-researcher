# CRM を Cloudflare に移す（第1段階）

2026-10-07 着手。顧客名などの個人情報はこのファイルに書かないこと（git に入る）。

## ねらい
- CRM（今は GAS の `?action=crm`、開くのに15秒前後）を、Cloudflare の普通の Web ページにする。
- 開く 1〜2 秒、外の変化（Discord からの送信・LINE の返信・条件変更）もほぼ自動で反映。
- 将来スマホで使う・通知を出すための土台。

## 方針（第1段階）
- **本物はスプレッドシートのまま**。Cloudflare の D1 は「写し」。
  - LINE の受け口・拡張・Discord 承認ページ・トリガーなど、今シートを書いている所は**変えない**。
- **読むのは D1、書くのは GAS**。
  - CRM の画面は D1 の写しを Worker から受け取り、**樹形図の組み立てはブラウザ**でやる
    （Workers 無料の CPU 上限は 1 回 10ms。サーバーで全員分を組み立てると超える）。
  - CRM のボタン（記録・送信・条件保存など）は、今ある GAS の関数を GAS の Web アプリ経由で呼ぶ
    （`doPost action=crm_call {fn, args}`）。GAS がシートを書く → 写しが D1 に届く → 画面に出る。
  - 画面は今と同じく「押したら先に変える・保存は順番待ちの列」。
- **写しの送り方**
  - 小さいシート（検索条件・対応ログ・LINE 系・タスク・グループ・メモ・問い合わせ など）:
    変わったら丸ごと送る（数百行・数百KB以下）。
  - 承認待ち物件（3,465行・約30MB）: 行ごとに送る（追加・状態変更・写真・一言・直した項目）。
    行の削除（片付け）のあとは丸ごと送り直す。
  - 夜に 1 回、全部を丸ごと照らし合わせて、送り漏れのずれを直す。
- **データベースの形（はじめは素朴に）**
  - `sheet_rows(sheet, r, v)` … シート名・行番号・行の中身（JSON 配列）。GAS の getValues() と同じ形にして、
    今の CrmTree.js / CrmSend.js の組み立てを、ほぼそのままブラウザへ移せるようにする。
  - `sheet_meta(sheet, rows, synced_at)` … 最後に送った時刻。
- **ログイン（第1段階）**: 今と同じ鍵（api_key）方式。最初に鍵付きの URL で開くと、以後は Cookie で入れる。
  スマホ対応のときに Cloudflare Access（Google ログイン）へ切り替える。

## 量（2026-10-07 測定、上限見積り）
- 全シート合計 約 39MB（承認待ち物件 約 30MB が大半）。D1 無料の 500MB に収まる。
- 書き込み: 承認待ちの丸ごと送り直しは 1 回 3,465 行。1日10万行の上限があるので、丸ごとは夜の 1 回と片付け後だけ。

## 手順
1. Worker + D1 の土台、写しを受け取る口（`POST /sync`）。GAS から全シートを丸ごと送る関数（手動・夜のトリガー）。
2. GAS の書き込み口で、変わった行・シートを送る（`_crmTouch_` の場所が目安）。
3. 樹形図の組み立てをブラウザ用に移す（CrmTree.js / CrmSend.js / 必要な コード.js の関数）。今の画面（CrmTreePage.html）を土台に。
4. 書き込みを GAS 経由に（`crm_call`）。
5. 今の GAS 版と並べて見比べ、同じ人数・同じ段に並ぶことを確かめてから切り替える。GAS 版は当面残す。

## 置き場所
- このフォルダ（`~/crm-worker/`）。GAS のデプロイ（gas_deploy.sh）はホーム直下の .js/.html だけを送るので混ざらない。
- Cloudflare アカウントは画像置き場（ehomaki-img）と同じ。アドレスは workers.dev の無料のもの。
